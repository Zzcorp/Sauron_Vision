{% comment %} The money question, answered in one card on both money pages. Renders the `capital` context (portfolio.services.capital_summary) — the POOL economy (allocated to enabled configs / committed to open tickets / uncommitted, per asset class AND per mode) beside the BOOK economy (cash, book value). The headband popups quote the same service, so a popup and the page it links to can never disagree. None renders as an em-dash: an unreadable pool table is "not measured", never 0. The wrapper region sits OUTSIDE the {% if capital %} guard on purpose: live_region.apply() leaves a region alone when the payload lacks it, so a transiently unreadable pool must still ship the (empty) region or the card freezes at its last reading forever. Tone classes live on elements INSIDE the region — the swap copies innerHTML, not attributes. {% endcomment %}
