HTML5 measures `step` from the STEP BASE, and the step base is `min` when one is present — so `min="0.1" step="1"` admits 0.1, 1.1, 2.1 and nothing else. Three of these four fields rendered their own shipped default as an invalid value: 100 and 20 against a 0.1 base stepping by 1, and 0.7 against a 0.01 base stepping by 0.05. The browser refused to submit the form at all, silently, on a page whose entire purpose is setting these numbers. Fractional steps would technically fit but reintroduce the same class of bug the moment a default moves, and floating-point step validation is where browsers disagree with each other. The range is still enforced by min/max here and re-validated server-side, which is where it has to hold anyway. {% endcomment %}
