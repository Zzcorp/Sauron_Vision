{% comment %} Position Analytics — the fragment /htmx/metrics/positions/ swaps into the bottom of /positions/. It used to be a Chart.js bar of open P&L above a six-column copy of the table already on the page, and it had never drawn either: the view's query raised on every request and the empty branch was all anyone ever saw. Three things changed with the rebuild. * A FAILURE IS SHOWN. `error` renders as a sentence at the top of the panel. The old view put its exception in the same context key and nothing read it back out, so a broken query and an empty book produced identical markup — which is exactly how a permanent FieldError went unnoticed. * IT SAYS SOMETHING THE TABLE CANNOT. The table above prints one row per position; this answers where the money is concentrated, how the book is spread across R, which way the exposure leans BY VALUE (the donut at the top of the page divides it by count), and how long it has all been sitting. Every figure is formatted in the view, so the em-dash rule for an unmeasured value lives in one place instead of in a dozen template branches, each a fresh chance to print a confident zero. * THE CHARTS ARE THE HOUSE PARTIALS. They carry the theme tokens, the viewBox geometry, and — unlike a canvas — the distinction between a measured zero and a reading that was never taken. This fragment lands INSIDE the page's "Position Analytics" card, so it uses plain sections rather than cards of its own: a .card here would draw a second border, a second accent line and a second 22px of padding inside the first. {% endcomment %} {% if error %}
